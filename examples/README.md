# Примеры использования jam/dbsimple-models

Каждый файл — самостоятельный сценарий, который печатает выполняемый SQL и результаты.
Примеры работают на SQLite в памяти, ничего устанавливать не нужно:

```bash
composer install
php examples/06-eager-loading.php     # один пример
composer examples                     # прогнать все (их же запускает тест ExamplesTest)
```

В реальном проекте вместо SQLite используется MySQL через `Jam\DbSimple\Connect` —
см. комментарий в [`bootstrap.php`](bootstrap.php).

## Best practices

**Модели**

- Заведите свой базовый класс (`BaseModel extends Model`): там переопределяется
  `freshTimestamp()` и живут общие хелперы вроде `findOrFail()`.
- `$fields` — **полный** список колонок таблицы. Выборки идут через `SELECT *`, и колонка,
  которой нет в `$fields`, даст `ModelException` при чтении. Добавили колонку миграцией — добавьте в `$fields`.
- Связи объявляйте в конструкторе **до** `parent::__construct($data)` — иначе вложенные массивы
  из `$data` не превратятся в модели.
- Повторяющиеся условия оформляйте «скоупами» — статическими методами, возвращающими построитель
  (`Post::published()->orderBy('id')->all()`).
- Пароли и прочие чувствительные поля: `$hidden` (не уходит в `toArray()`) + `$guarded`
  (нельзя присвоить снаружи). Запись — методом модели через `$this->fromArray([...])`.
- Для pivot-таблицы заведите собственный `id`: после вставки ORM присваивает модели первичный ключ.

**Запросы**

- Простые условия задавайте массивом: `where(['user_id' => $id, 'status' => [1, 2]])`. Такое условие
  работает в любом хранилище (SQL, DummyModel, будущий MongoDB), SQL-фрагмент — только в SQL.
- В SQL-фрагментах всегда используйте плейсхолдеры (`?`, `?d`, `?a`, `?#`) — никакой конкатенации значений.
- Необязательные фильтры — через условные блоки `{ AND col = ? }` и `DBSIMPLE_SKIP`.
- Построитель сбрасывает состояние после выборки; агрегаты (`count()` и др.) — только себя.
  Это позволяет посчитать `total` и выбрать страницу теми же условиями (см. 03).
- Если порядок важен — задавайте его явно, в том числе для связей: `with('tags:o(name)')`.
  Без `ORDER BY` MySQL вернёт строки в порядке индекса.
- Колонки из JOIN-таблиц забирайте `collectionRaw()`/`firstRaw()`: у модели их нет в `$fields`.

**Связи**

- Связи не загружаются лениво: всё, что нужно, перечисляйте в `with()`. Каждая связь — один запрос
  на всю выборку, N+1 исключён.
- Ограничивайте поля связей: `with('author(id, name)')` — ключи связей добавятся сами.
- Не размазывайте строки `with` по контроллерам: заведите у модели with-профиль —
  статический метод с параметрами (`Post::commonWithString(viewerId: $me, comments: true)`),
  который собирает выражение. Вызывающий код решает, какие ветви графа нужны, модель — как они выглядят (см. 11).
- Профиль принимает `$name` — путь, к которому он прикрепляется (`ArrayHelper::extendsWithName()`),
  так один профиль переиспользуется внутри другого (`posts:o(id)`, `author`, `subject`).
  Во вложенный профиль передавайте полный путь, а не применяйте `extendsWithName()` к уже склеенной строке.
- Один и тот же путь можно упоминать многократно (`author(id, name)`, `author.role`) — узлы сливаются.
  Условие и флаги узла задавайте в одном месте.
- `l(N)` в `with()` ограничивает **весь** запрос связи, а не «N записей на родителя».
- Отсутствующая связь — `null` (а не пустой список): используйте `?->` / `?? []`
  или маркер `!` для `toArray()`.

**Сохранение**

- `save()` существующей записи пишет **все загруженные** поля. Чтобы обновить конкретные — `update('a, b')`.
- `null` в поле означает «не трогать», для записи `NULL` используйте `Model::NULL_VALUE`.
- `save()` рекурсивно сохраняет все загруженные связи. Если связи загружены только для чтения —
  `$model->save([], false)`. Для существующего родителя присваивайте ключ (`user_id`), а не модель.
- Удаление «лишних» детей/pivot-строк — только по запросу: `save([Model::SAVE_USE_CHECK_OLD => true])`.
- Реплика — только для чтения. Модель, прочитанную с реплики, не сохраняйте в master:
  перечитайте её из master.

## Шпаргалка

### `with()`

```
alias[условие](поля)^исключения^?!:флаги.вложенная, другая
```

| Часть | Пример | Значение |
|-------|--------|----------|
| `[...]` | `comments[is_approved = 1]` | условие для связанной таблицы; `this(field)` — поле родителя |
| `(...)` | `author(id, name)` | выбираемые поля |
| `^...^` | `author^email, phone^` | исключить поля из `toArray()` |
| `?` | `profile?` | неизвестный алиас не бросает исключение |
| `!` | `profile!` | в `toArray()` — `{}`/`[]` вместо отсутствующей связи |
| `:o(...)` | `:o(views DESC\|id)` | сортировка (запятая внутри аргумента — `\|`) |
| `:l(N)`, `:f(N)` | `:l(10)` | лимит/смещение запроса связи |
| `:k(field)` | `:k(id)` | ключи массива в `toArray()` |
| `:c` | `posts:c` | computed-поля связи |
| `:p` | `tags:p` | строки pivot-таблицы в `@pivot` |
| `:r` | `posts:r` | вместе с soft-deleted |

### Условия-массивы `where([...])`

| Запись | SQL |
|--------|-----|
| `['user_id' => 5]` | `` `user_id` = 5 `` |
| `['status' => [1, 2]]` | `` `status` IN (1, 2) ``; пустой список — ничего не найдено |
| `['deleted_at' => null]` / `['deleted_at' => ['!=' => null]]` | `IS NULL` / `IS NOT NULL` |
| `['views' => ['>=' => 10, '<' => 100]]` | `` `views` >= 10 AND `views` < 100 `` |
| `['title' => ['like' => 'PHP%']]`, `'not like'`, `'not in'`, `'!='` | соответствующие операторы |
| `['p.user_id' => 5]` | поле с алиасом таблицы |
| `[Criteria::OR => [['a' => 1], ['b' => 2]]]` | `` ((`a` = 1) OR (`b` = 2)) `` |

### Флаги `toArray()`

| Флаг | Значение |
|------|----------|
| `d` | связи (по умолчанию включён, **только если флаги не переданы**) |
| `c` | computed-поля (не наследуется связями) |
| `h` | hidden-поля; `h(a\|b)` — только перечисленные |
| `x` | extra-поля |
| `e` | выводить поля со значением `null` |
| `s` | Stringable: числовые коды → строки |
| `_` | значения «как в БД», без кастов |
